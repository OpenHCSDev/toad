# Toad maintenance: descendant and stuck-spawn safety contract

**Status: isolated design/probes only.** This does not modify reviewed Toad PR67 or the merged Comms core, enable a marker, provide a production operator, or authorize a maintenance window. PR67's new-code lock gives an atomic spawn-vs-pause boundary, not a global retired-child proof.

## Disposable evidence on this Linux host

- The independently owned marker-only `setsid` ACP descendant survives PR67's shell-group cancellation while the shell exits and the wire admission lock releases. Its pidfd remains unreadable until the fixture kills it explicitly. Script `/var/tmp/toad-maint-independent-da529/escaped_child.py` (test-owned PID/group cleanup).
- An initial `tests/maintenance_namespace_probe.py` run under **system Python 3.14.6** created an unprivileged user+PID namespace; its distinct PID1 kill was followed by readable pidfds for PID1 and a marker-only `setsid` PID2. That initial script had unsafe numeric-PID cleanup and the positive log is **quarantined, not independently accepted**; the corrected successor adds `--kill-child`, pidfd-only target signaling/cleanup and a post-setsid readiness handshake, but must not execute again before independent safety review. Replacing `unshare` with `/bin/false` produces finite BLOCKED before PID1. `/sys/fs/cgroup` is not writable to this process; a privileged operator may exist but no OS-separated cgroup controller is provisioned. **Python pidfd APIs depend on the interpreter**: system Python 3.14.6 exposes `os.pidfd_open` and `signal.pidfd_send_signal`, while pinned disposable Toad Python 3.14.2 and Comms Python 3.11 do not. The pinned runtime prints BLOCKED before attempting unshare; an alternate syscall/libc bridge would require separate design and review. A shell pidfd alone cannot own escaped descendants.
- An initial `tests/maintenance_stuck_spawn_probe.py` run injected a fake blocking OS spawn inside PR67's admission context. Its original pause process had no contender-entered proof and cleanup used raw process-group signals; that positive log is also **quarantined**. The corrected successor writes a marker inside the test-only fixture wire-lock acquisition call and retires only tracked unreaped disposable Python processes through their `Popen` handles. It awaits independent safety review before rerunning. Even a safe positive would prove fail-closed admission, **not bounded liveness**: a real indefinitely stuck Popen can hold pause forever, and if it launched a child before returning, the caller has no child PID or retirement proof.
- **Quarantined historical** provider-free log: `/var/tmp/toad-child-retirement-final-controls-20260926.log` SHA256 `288e3d6bd632f786156a2f7825cf8e4f0dfd95eb0d53965c14b620096abda686`. Corrected `tests/maintenance_cleanup_signal_regression.py` uses signal-recording mocks only; all three controls pass under system Python. ## Required authority before any pause acknowledgment

An external maintenance controller must first stop/deny **all** Toad UI, reconnect, CLI, ACP and old-import-capable ingress; the new-core gate cannot retroactively constrain old clients. Every admitted, potentially provider-capable ACP child must then have an immutable identity and terminal proof. Neither a shell `wait()`, process-group disappearance, `active_turn=None`, nor a saved STOPPED row is sufficient. An uncertain child/attempt remains UNKNOWN and holds maintenance closed; do not replay its original input or release merely after a timeout.

For a possible Linux-only successor, a **dedicated per-ACP PID namespace** is the containment boundary. This is not proven by the probes above and needs its own isolated implementation and review:

1. Launch an external guardian/supervisor with a pre-armed absolute-deadline watcher **before** any potentially blocking Popen. Spawn a dedicated `unshare --user --map-root-user --pid --fork --mount-proc` intermediary, preferably with `--kill-child`, with a staged namespace PID1 that cannot execute the ACP command until a one-shot release. The guardian and intermediary must not claim Armed merely because a process was forked.
2. Bind an operation nonce, exact Toad session, child environment/canonical cwd, original input authority, guardian/intermediary/PID1 process-start identities and live pidfds to one admission receipt. Before releasing the staged ACP executable, independently verify distinct PID namespace inode, namespace PID1 (`NSpid` terminal component 1), ready-token provenance, live PID1 pidfd, and watchdog armed. A failed/denied namespace or mismatched identity declines without executing ACP. No `getAuth`, provider request, or queued turn is part of readiness.
3. The watchdog must be independent of a blocked Popen return. On cancellation, deadline, guardian death, or UNKNOWN launch acknowledgment, hold admission closed and retire the exact namespace PID1 via pidfd_send_signal (or an equivalently identity-safe operator), then verify its exit and absence of live members in that namespace, including setsid descendants. A host process-group kill, shell PID alone, or mutable `EventStream` result is not completion authority. If an inspector fails, quarantine and require owner-only repair rather than returning an open receipt.
4. Only after exact namespace/child retirement plus the Comms durable turn/input disposition is known may the controller count that admission as drained. A crashed controller, old-import process, untriaged provider side effect, or incomplete rollback keeps the durable barrier closed. Reopen requires a separately reviewed OS-separated operator/control-plane capability and a user-authorized maintenance window; the production Comms package intentionally exposes no public begin/advance/reopen writer.

## Required independent acceptance, still missing

- Repeat the setsid marker-child negative on PR67 and positive in the proposed dedicated namespace; include nested namespaces, owner crash, PID reuse, and unrelated process protection. Verify descendant pidfd exit, not only `kill(pid, 0)` (which also succeeds for zombies).
- Fault-inject `unshare` denial, fake PID1/namespace token, duplicate release, delayed Popen return beyond deadline, watcher death before/after Arm, blocked Popen indefinitely, and staged executable release after expiry. No native marker may execute late and no pause may ACK with live namespace members; UNKNOWN cannot be retried.
- Pair exact Toad source, merged Comms wheel and a host-specific OS capability receipt. Demonstrate real ACP stdio/reconnect behavior without provider calls, then independent full-ingress old-client exclusion and operator authorization. Unsupported macOS/Windows or hosts denying user/PID namespaces must fail closed unless a distinct independently reviewed containment mechanism exists.

**Finite blocker:** An initial system-Python disposable run suggests this host permits a user/PID namespace and PID1 teardown of a setsid child, but its unsafe cleanup prevents acceptance until the identity-safe successor is independently reviewed and rerun; the pinned Toad runtime additionally lacks Python pidfd APIs. PR67 has no guardian, staged-exec handshake, immutable namespace-init pidfd, independent pre-Popen watcher, or proof that a real ACP child and all descendants were retired. A stuck Popen can block the new-code pause forever; an escaped child can remain provider-capable after PR67 returns. Therefore no bounded retirement or global maintenance ACK can be asserted from the present implementation. Keep PR67 default OFF and live activation on hold.
