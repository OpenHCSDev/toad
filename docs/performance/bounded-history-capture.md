# Root-only history/frame observation

This is an observation tool, not a history performance repair. Authors do not run it. Root reviews the exact head, selects the private-process controls below, and only then attaches to its explicitly selected copied-bus frontend. No synthetic app, UI input, screenshots, provider calls, saved-history decoding or service operations are involved.

**Xvfb isolates the display, not data.** Root's earlier frontend used the published bus and user XDG paths; merely painting marked human reads. Every future root frontend must use an existing copied bus through `--comms-root` AND separate `XDG_STATE_HOME`, `XDG_CONFIG_HOME` and `XDG_DATA_HOME`. Copy the real saved history, never operate on the original. Neither the observer nor an author may launch, attach or send input against the live root. Preserve original human read markers and XDG files; do not manually restore or rewrite them. An earlier successful collector run is not proof of data isolation.

## Owners and first split

`frame_meter.BoundedCapture` owns admission, encoded record bytes, weak labels, timers, hook restoration and atomic publication. Both public entrypoints accept `max_records`, `max_bytes`, `metadata_only` and return its idempotent bound `finish` method. `MethodTarget` owns descriptor preservation and inherited-declaration restoration. Metadata adapters register their target at subclass declaration; there is no separate target roster in the launcher.

`history_capture_remote.RemoteCaptureRun` owns completion. Its run directory fixes `complete.json` at construction. Duration, failed setup and explicit controller cleanup all call its one `finish`: restore handles once, preserve the first status, publish that same canonical completion, then retire the in-memory owner. A failed publication leaves the completed owner reachable without restoring hooks twice. `read_completion` owns the bounded file read and matching-token check; operation-specific replies are only views of this completion, never another completion decision.

`history_capture_remote.CaptureSpec` is the one frozen, data-only selection for duration and the frame/call record and byte limits. Its dataclass fields derive the controller's CLI arguments and defaults. `CaptureRequest` carries that same value through FieldCodec into both immutable copied requests; manifest, entered receipt, collectors and group timer consume it rather than restating the limits. `ProcessIdentity` carries PID/boot/start ticks. The nominal `CaptureOperation` members own remote start and cleanup, and derive request-script names; there is no second operation roster or raw request-key reader.

The source declarations used are:

- `PreparedPageSource.get`: source/scope, request end/cursor; the result is the actual `PreparedTranscriptPage` passed to row preparation.
- `PreparedTranscriptPage.prepare_rows`: the same weak page label, cursors, fragment count, actual selected-category identity, direction, target width, requested rows and returned rows.
- `LineHistory._load_page`: inclusive parent span, history/source/scope/filter identity and width. `needs_more` is its boolean return, **not** proof of publication.
- `LineHistory._extend_and_trim`: actual staged page label and local/source growth. `TranscriptSourcePreparation.rows_published` joins through that history and `_load_page` parent. A row-admission event is not completed layout.
- `ToadApp.select_session` / `_switch_mode_ready`, `SwitchToast.show`: natural tab request/switch and toast duration, never title/body serialization.
- `FramePresentation.written` and `_FlushSignal.deliver`: UI acknowledgement versus writer-thread flush signal. Neither is pixels.
- Frame/input/layout hooks remain in `install`. A frame sample requires an actual successful `LinuxDriver.write` directly from the declared `App._display` code. Merely entering `_display`, headless publication, a batch-gated call, or begin/end-update control writes cannot create a sample.

Labels are local to each output, use monotonically assigned integers and weak references, and emit identity/retirement records. No product object is retained or hashed. Unsupported weak lifetimes are `null`, not bare reusable `id()` values. Cross-file correlation uses the common monotonic clock, not coincident label integers. `ValueMetadata`, declared once at the lazy observation boundary, uses the existing `MroProjection`/`handles` mechanism. Native `TranscriptPage`/`TranscriptCursor` retain native byte offset, assigned wire sequence and selected witness scalars. `WirePage`/`WireCut` use their actual `source`/`cursor` declarations; `PageCursor` supplies lower/upper/history-source capabilities, including live, historical and unread cuts. `PreparedWirePage` inherits the shared prepared-page handler. `MessagePage` contributes selected evidence type, message count and derived endpoint cursors, never message bodies. Missing values are explicit absent records; other unsupported classes emit a bounded type/unsupported record instead of probing native fields or stopping the capture. Snapshot identity is a weak label, not a serialized `TranscriptReadIdentity`.

Parent spans are inclusive. Awaited thread CPU includes other work on that thread during suspension; it is not exclusive task CPU. Never add nested/concurrent durations. A first later display is a temporal candidate, not evidence that the same page geometry was painted. This first split can identify a dominant inclusive term; it cannot prove pixels, exact child cost, lock wait, ready-hit/eviction or a usable-page deadline. Missing page match, no older edge, zero frames or exhausted caps means inconclusive attribution, not success.

## Bounds and lifecycle, from the source (not executed proof)

1. Each record is JSON-encoded once using compact separators and UTF-8 before admission. Retained buffers contain only those bytes. No mutable nested product records are admitted. Metadata records have a fixed scalar shape, bounded names/paths, and no event/message/fragment bodies.
2. `used` starts with the exact static envelope and every stream's key/brackets/separators. Each admitted record charges its encoded length plus its actual comma. Admission requires `used + incoming + FINAL_RESERVE <= max_bytes` and count below `max_records`. A cap stops admission immediately, even when restoration must await the UI loop.
3. `FINAL_RESERVE` is 8192 bytes for status/key/separators. Status fields are bounded strings, scalar clocks/counts and booleans; output byte count includes its own decimal spelling via fixed-point accounting. Hooks are already restored before writing. Output streams directly to one exclusive `.partial` and is renamed; no second bulk output is made.
4. Exact count/cap/error/censored-open-span/censored-input status is retained. Work occurring after close is unobserved, not falsely counted as zero drops. No record is appended by a late async completion. Async wrappers still return/cancel/raise through the original function.
5. All descriptors, target existence and running loop are checked before patching. Each installed hook remembers the original descriptor and whether it was inherited. Reverse restoration only replaces this capture's exact wrapper; a later wrapper is left alone and reported as superseded. Timer, explicit finish, admission error, cap and partial setup use the same owner.
6. Metadata collection does not start a stall watcher, install a GC callback, call `gc.get_objects`, traverse a heap, inspect coroutine locals, walk arbitrary dataclasses, or call `_subject`, `_field`, `_result` or product `repr`. Old standalone heap diagnostic functions remain explicit opt-ins; this launcher never invokes them.
7. Legacy `trace_calls(metadata_only=False)` retains its six-column JSON array. Metadata mode uses a `calls/events/pauses/capture` envelope. Existing frame/input/lag array shapes and `summarize` remain; immutable input-handler completions are coalesced by arrival using the last observed handler end. Intrusive stack/heap diagnostics are no longer part of `install`; flat bounded events replace those unbounded maps.
8. `measuring_pause` borrows each active capped lifetime. Start markers, closed interval pairs and open interval IDs share its record/byte limits; there is no uncapped global interval list. Finish retains the earliest open/censored start and the admission-end clock in the reserved scalar footer: all unfinished exclusions overlap that end, so one union interval suffices. Nested intervals are bounded by admitted starts; late ends cannot alter a sealed capture. `summarize` preserves the complete capture status, excludes closed/censored pauses (including input-to-handoff crossings), and reports absent switch samples or historical missing exclusions as `unobserved`, not zero.
9. `BoundedCapture.complete_span` holds the existing `RLock` across accepting check, terminal admission, open-span retirement and censorship. Metadata errors and cap exhaustion remain inside that same transaction. Entry also checks admission under this lock; a wrapper losing the race with finish does not allocate an observed span. Finish cannot see a terminal record while still counting that same span as open.

## Root launch and recovery

Use the reviewed `tools/performance/capture_history.py` with the explicit copied-bus/private-XDG frontend PID, boot ID, `/proc/PID/stat` start ticks, canonical installed runtime directory and exact approved meter SHA256. Root must establish copied-bus and all three XDG paths before any launch or attach; the capture arguments below do not establish that isolation. The launcher checks the meter AST interface/hash and process birth/mapped runtime before any attach; unsupported contract fails before `sys.remote_exec`.

```
python tools/performance/capture_history.py start --approved \
  --pid CURRENT_PID --boot CURRENT_BOOT --start-ticks CURRENT_TICKS \
  --runtime /absolute/canonical/runtime \
  --meter /reviewed/checkout/tools/performance/frame_meter.py --sha256 APPROVED_SHA256 \
  --output /home/ts/.cache/agent-scratch/ROOT_OWNER/p903-UNIQUE
```

The controller writes immutable typed requests and copies `history_capture_remote.py` as `start.py` and **`cleanup.py`** in that run directory. Only copies with an adjacent request execute remote work; ordinary import performs no attachment. Both file boundaries decode `CaptureRequest` with the existing FieldCodec; there are no compatibility readers for older requests. Root must preserve the original recovery scripts with their original requests after uncertainty, never replace them with a new revision or retry their starts.

`CaptureSpec` owns the shared allowances: attach helper 5s, completion grace 3s, cleanup receipt 2s, poll interval 250ms. Observation budget is `attach_timeout + seconds + completion_grace`; cleanup budget is `attach_timeout + cleanup_receipt_timeout`; controller budget is their sum. Default selection therefore has a 33s observation wait and a 40s controller wait budget, rather than unrelated 28/35 literals. These bound waits, not arbitrary filesystem/scheduler latency. Root runs the command in the background; an external timeout must allow the cleanup budget, and interrupting a helper never proves remote code did not run. The helper's bounded stderr/exception cause is retained in the existing controller status, including EPERM, nonzero exit and timeout. Setup failures retain their cause in the complete result even if that file appears before the separate failure receipt. No arbitrary product representation or traceback enters the receipt.

The target rechecks birth/runtime, all loaded Toad/Textual/Core module locations, the meter hash and actual descriptors before patching. At the foreign module boundary, `require_modules` requires a real `ModuleSpec`: its concrete `origin` when `has_location`, otherwise every namespace `submodule_search_locations` entry. The applicable set must be nonempty and **every** resolved location must lie inside the selected runtime. A namespace such as `agent_comms.skills` is not rejected just for lacking `__file__`; it gets no spelling exemption either. Missing specs/locations, mixed or outside locations and missing `toad.app` fail closed. Controller and target use the same size-bounded source reader (256KiB plus one overflow byte). The target compiles and executes exactly that verified buffer with its registered module namespace and `__file__`; neither loader reread nor cached bytecode can replace the approved bytes. Metadata imports and actual descriptors are checked before the first patch and followed by another provenance check. Locations prove provenance, **not a hash of already-loaded code**. No particular conversation is required to obtain global frames; source mismatch and absence of an older page remain visible/inconclusive.

Default parity: `CaptureSpec` selects 25s, 20,000 frame records, 20,000 call records, 3MiB frames and 12MiB calls. Two code copies, two bounded requests and all bounded receipts reserve less than 1MiB, so default partial/final output and metadata fit 16MiB. CLI field names derive directly: `--seconds`, `--frames-max-records`, `--calls-max-records`, `--frames-max-bytes`, `--calls-max-bytes`. Foreign CLI/JSON values must have their declared scalar types and be finite and positive before setup. BoundedCapture still enforces its existing physical ceilings and byte accounting; neither collector algorithm changes. Invalid physical limits fail during its setup and use the same restoration path if another collector was already armed. No ceiling values are copied into CaptureSpec.

For root to choose **after** a fresh isolated qualification measures actual frame rate, bytes and overhead, an example long selection is 900s, 500,000 frame records/64MiB and 200,000 call records/64MiB. This gives a 908s observation wait and 915s controller wait budget, with less than 129MiB reserved output. The current meter's 4ms lag probe also spends the frame record budget; a large seconds flag alone never guarantees exposure. Use a fresh selected PID/birth and directory, with the same identity/runtime/meter/hash arguments as above:

```
timeout -s INT 915 python tools/performance/capture_history.py start --approved \
  --pid CURRENT_PID --boot CURRENT_BOOT --start-ticks CURRENT_TICKS \
  --runtime /absolute/canonical/runtime \
  --meter /reviewed/checkout/tools/performance/frame_meter.py --sha256 APPROVED_SHA256 \
  --seconds 900 --frames-max-records 500000 --calls-max-records 200000 \
  --frames-max-bytes 67108864 --calls-max-bytes 67108864 \
  --output /home/ts/.cache/agent-scratch/ROOT_OWNER/p948-UNIQUE
```

A second terminal can derive the selected wait budget without attaching: import `CaptureSpec`, construct it with the same CLI selection and read `controller_budget`. The example 915 is this formula's result, not a second code default. An external timeout can interrupt final publication; inspect retained status and use the distinct cleanup operation below if restoration is unconfirmed. Neither 900s nor a successful footer proves 10,000 loaded frames. Actual caps, censorship, interval, count and concurrent N/M determine the evidence; cap exhaustion is inconclusive. Descriptive nearest-rank p99.9 is sorted sample rank `ceil(.999*n)` (one-based), and equals the maximum when n<1000. At 10,000 frames only about ten expected exceedances support that tail; do not assert independent-sample confidence for correlated frames.

Root may start existing read-only external py-spy concurrently **after** `entered.json` and correlate its start/end clocks with the same frame interval. `capture_live.py` runs profiling before its meter if both options are supplied, so that combination is not contemporaneous. Keep nested inclusive profile/call/layout durations separate. The bounded meter has no GC stream: old GC captures are leads, not a current cause. No GC/heap callback, scheduling experiment or new meter is introduced here.

For a separate explicitly authorized recovery after inspection:

```
python tools/performance/capture_history.py cleanup --approved --output SAME_RUN_DIRECTORY
```

The ordinary controller cleanup first reads the matching-token canonical completion, before any process-birth check or attach. If present, it returns that original result without another remote operation, even if the process has since exited. Otherwise it checks birth, makes ONE distinct cleanup attachment and waits only for canonical completion, never a pre-existing `cleanup-result.json`. Remote cleanup likewise returns the active owner's `finish` result, or derives it from matching-token `complete.json`; absent completion stays explicitly unconfirmed. The operation-specific reply uses that returned status and cannot overwrite canonical completion with a later failure.

The actual race exposed by root's invalidated profile calibration was: first cleanup restored 20 hooks but wrote only `cleanup-result.json`; its owner retired without `complete.json`; a second controller cleanup returned the old positive reply before its own remote operation ran; that operation then wrote `token-not-present`. Binding the completion path to RemoteCaptureRun deletes the caller-selected publication path and the controller's stale reply reader. The calibration also had a 49Hz profiler overrun of 48.5s and no speedscope artifact: it is not performance evidence or a meter-algorithm defect.

Do not retry a start or kill the frontend. A blocked/uninterruptible target may not execute either the duration timer or remote cleanup. `CLEANUP_UNCONFIRMED` is a real possible result; keeping a recovery script is not proof hooks were restored. A missing token does not prove an uncertain attach had no effect. Read each capture's `cleanup`, failed/superseded hook counts and cap/error fields in canonical completion, not just a group `FINISHED` label. Preserve every original failed-run directory, request and recovery script; new source is not permission to replace or replay an old recovery protocol.

Root still owes this correction's actual copied-bus/private-XDG qualification: normal duration finish; explicit early cleanup then cleanup again; failed setup then cleanup; scalar/output-bound controls; every hook restored; original human read ledger and XDG files unchanged. No author test, attach or performance completion is claimed.
