## Source findings

Existing SessionTracker owns sessions, original SessionDetails, index and mutation. App creates a Textual Signal and injects it; tracker publishes tuples of mode and mutable details (or None for close), while SessionAdmissions publishes creation separately. Tabs and SidebarObservation ignore those payload details and read the current canonical application projection. Therefore the tuple repeats a changing state object without providing consumer behavior.

The coherent first batch puts all new/update/close publication on SessionTracker.events. SessionChangedEvent identifies the original mode only, and SessionClosedEvent inherits that invalidation. Existing tabs/sidebar consumers read the original tracker/projection. App's session_update_signal and consumer tuple types are deleted, as is the admission owner's extra creation publication. No second metadata store, status value or event history.

Existing Textual Signal is the only local subscriber mechanism; core/dependency source searches found no UI-independent application subscription owner (native runtime.subscribe is a network operation, not this mechanism). CoreEventStream and its Subscription therefore own genuinely missing headless publication and subscriber resource lifetime. They use a weak subscription collection; the subscriber retains and closes its resource. No queue, timer, state replay or topic registry. Every event is a declared dataclass: FieldCodec already supplies the family discriminator, record wire fields and schema; no custom codec/representation.

One CoreEventMessage carries the original event unchanged. Existing MroDispatch owns handler selection; CoreEventReceiver owns message-pump delivery and unmount teardown. Its subscriber collection is a frontend resource, not semantic state. Textual's native handler MRO calls both mixin and Widget unmount methods; original widget worker teardown remains. Original Signal scheduled native callbacks; the replacement uses the same native message pump, with async consumers serialized there. Generic propagation follows the original native parent route; unmatched consumers use MroDispatch's existing no-handler behavior rather than a second event policy.

SidebarState's sole restore_scroll consumer was SidebarNavigation, and the method acted on native Widget resources. Move that existing operation to its actual native navigation owner and delete the state method and Widget import. This frees all of SessionTracker's imports without claiming broader U2 closure.
