Baseline: published frontend 1ec/main625, installed default Core3e/native0f.
Candidate keeps those exact Core/native wheels, SDK0.12.1 and Python3.14.2.
No global package changes, owner restart, source/session fork or submitted input.

## Source and decision

AgentProcess acquires a connection with original command/env/cwd/route custody.
AgentSession.initialize keeps the response on that connection; initialization
builds capabilities through Core SessionLifecycle, without reading history.
Load attaches to the existing owner; ordered notification validation and the
independent response metadata decoder retain their distinct contracts.
SnapshotPublication validates captured source/native resources before and after
worker preparation, mounts provisional history, commits coverage, retires the
original captured cohort and calls painted. None of these decisions changed.
TranscriptHistory uses PreparedContentRange.initial_slice(newest=True), retaining
four recent fragments, or restores original reader admission. Its body preparation
uses SnapshotPublication's actual selected categories. Metadata/tool disclosures
retain their original lazy owners. No recent-first loader correction was needed.

Actual two Markdown bodies were 24/241 characters. Their worker executes took
23ms each while first-use submission waited419/457ms. Removing unrelated editor
and patch imports alone did not reduce that delay. Import tracing then established
354/366ms importing render_tasks, principally required native Markdown/Textual.
Shared original worker initializer now acquires the rendering declarations beside
SDK ingress during bootstrap, before recent-page admission. Native editor and
patch implementation imports live in their original task execute/accept methods.
Both local and persistent renderers already use that same initializer. No dummy
job, task registry, decoder, adapter, cache or admission expansion was added.

## Qualification

Measured admitted-body preparation fell from395-462ms to39-40ms; publication
fell from492-590ms to97-116ms. Parent's earlier published run measured~800ms body
preparation. Total opening varied and has no demonstrated overall gain. Final
open had no App error, same147260275 frontier, four bodies and zero loaders.
Draft typing was accepted during attachment and restored before close; pilot.press
includes its own settling wait, so its301ms is not physical key-delivery latency.
App scheduling maximum64ms is not native wheel/layout acceptance.

Final initialize1.255s: instrumented Core imports1.175s, Comms construction43ms,
CommsClient construction5ms, initialize handler0.3ms. Bootstrap is still the
remaining large wait. Core608d/84 remains source checkpoints, not default backend.
This change does not claim to solve the reported five-second cold opening.

NRA SourceModule/module_syntax_index parsed862 production modules across Toad,
Core and native roots with zero omissions. Before/after import and consumer sites
are retained here; dynamic external imports are not an exhaustive behavioral proof.
Original Markdown, partition, patch and native document task execute/storage/result
acceptance passed in the candidate wheel. Persistent renderer execution remains
unverified here because optional ZMQRuntime is absent. Existing viewport, capture,
native layout, resource admission, notification order and currentness are untouched.

Owned disposable settings/state were removed. Candidate runtime/wheel and compact
raw timings remain at the named artifact path for integration; no other scratch
or retained evidence was removed.
