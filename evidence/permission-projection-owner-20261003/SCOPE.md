# PermissionRequest owns frontend projection admission and retirement

The existing request owns its future, permitted answers, actual projection callbacks and cancellation. Inline approval, diff review and the pending modal mount currently repeat decisions about whether that request is still pending, whether its binding is current and whether its view already presents it. Admission is checked before projection registration rather than reserving the original projection resource before asynchronous presentation.

Extend the original PermissionRequest to own acquisition through the existing SurfaceBinding capability, currentness, answer admission and actual callback retirement. Register the existing projection resource before any asynchronous native presentation. Native bindings and PermissionReview consume that owner; delete their repeated pending/current-binding policies. Conversation invokes the original request operation instead of selecting/dispatching a frontend itself. Preserve inline Ask and diff-screen resources, official ACP selection/cancellation outcomes, session replacement and detached request custody.

No new class, semantic state flag, projection registry, generic frontend framework, copied request or transport policy. Use the existing _projections callbacks as actual acquired resources. Keep distinct native focus/Ask layout state native. Extend SurfaceBinding with the native permission-binding invalidation hook only where it removes repeated lifecycle work.

Claims: permission_controller request methods, agent_surface permission methods, screens/permissions PermissionReview, and Conversation.request_permissions caller only. Do not change Heisenberg registration/compose/CSS/viewport methods or Kepler's history state. Existing refactor-audit AST across all production/test modules precedes edits; lexical ambiguities are explicit. Source semantics and the whole related family first, then one batched affected installed App permission/cancel/reattach check. Reuse this checkout and a released existing holder, no new environment/native copies/provider prompts/default changes. CI deferred.
