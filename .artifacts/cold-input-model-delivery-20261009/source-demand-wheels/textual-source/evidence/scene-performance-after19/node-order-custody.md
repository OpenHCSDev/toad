# Native child order is not child retirement

Heisenberg owns Textual21 NodeList/DOMNode/Widget integration; Toad298 owns retained sidebar row preparation. Existing classes were searched before implementation. `rg -n "\._sort\(|sort_children\(|\._remove\(|\._insert\(" src/textual` identifies one NodeList sorting declaration and its sole producer consumer DOMNode.sort_children, plus Widget.move_child using removal/reinsertion beside genuinely cross-parent reparent and final retirement. Native footer sorting and Toad SidebarGroup.reconcile_rows consume DOMNode's public algorithm. No second order catalog or state owner is introduced.

Required questions are whether actual native order changed, whether membership/custody changed, whether resource cardinality changed, and whether layout must publish a changed order. NodeList already owns all original child objects, keyed membership, projections, mutation generations and descendant cardinality. Previously move_child released/reacquired the same resource, ran the removal retirement hook, invalidated ancestors twice and changed descendant counts twice. Sorting invalidated even if its result was the existing identity order. Those operations disagree with the semantic custody transition.

NodeList now performs same-parent _move on its original order only, one generation update when changed, without touching membership/IDs/cardinality or removal callbacks. Its existing _sort commits a changed identity order and reports the operation result. Widget.move_child and DOMNode.sort_children request layout only after that native operation reports a change. Actual changes retain all existing layout invalidation. Invalid direction, foreign widgets, index errors and self-move validation remain on Widget; cross-parent reparent and final disposal retain original remove/insert ownership. No compatibility aliases, new type, retained order copy, renderer, clock, flags, cache or scene-map shortcut.

Patterns IDEN-1/IMPL-13: ordering and custody are distinct original facts; remove and insert consumer decisions are deleted rather than moved into another authority. New consumers inherit native NodeList ordering through DOMNode/Widget without re-deciding transitions. Production: 20 deleted, 23 added across three existing files.

Source reasoning and coherent implementation preceded one batched final native sanity: existing test_node_list and test_widget_child_moving, 36 passed in0.97s. The existing actual App custody journey now verifies same-parent movement does not call retirement, changed order updates once, unchanged adjacency/sort performs no layout request, and cardinality stays correct through reparent, virtual parent, mount and final removal. Explicit source Textual path plus owned existing sanity dependencies; this is not installed qualification. A changed paired installed public sidebar/frame journey remains required before Ready. No CPU or smoothness gain claim.
